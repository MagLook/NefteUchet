# TradeLedger — Архитектура

> **Дата актуализации:** 2026-03-27
> **Статус:** актуальный TL-контур после удаления legacy `НУ_*`

## 1. Назначение

`TradeLedger` — расширение для 1С:Бухгалтерии 3.0, которое загружает в базу:
- сменные отчёты АЗС;
- поступления топлива по ТТН;
- связанные документы движения и реализации.

Рабочий сценарий для бухгалтера остаётся простым: получить данные из API, создать документы, провести их из одной формы расширения.

## 2. Контур решения

Активный контур только один:
- префикс объектов: `TL_`;
- имя расширения при сборке: `TradeLedger`;
- актуальная XML-ветка: `xml-v4/`;
- каталог `xml/` оставлен только как архивный placeholder и в сборке не участвует.

Legacy-контур `НУ_*` удалён из `src/` и `xml/`. В рабочем дереве он может встречаться только как удалённые файлы в `git status`, пока изменения не закоммичены.

## 3. Источник данных

Расширение работает напрямую с API STS `https://pos.autooplata.ru/tms`.

Основные вызовы:
- `POST /v2/login` — получение JWT;
- `GET /v1/shifts` — список смен за период;
- `GET /v1/report/shift_report` — детальный сменный отчёт;
- `GET /v1/report/receipts` — поступления по смене.

Ключевые рабочие параметры для ООО «ГИГ» обычно задаются через регистр настроек:
- `system_id = 65`;
- соответствие станций;
- каналы оплат и соответствующие склады/виды операций.

## 4. Основные модули

| Объект | Роль |
|---|---|
| `TL_Загрузка` | Главная форма оператора: загрузка смен, ТТН, создание и проведение документов |
| `TL_НастройкаРасширения` | Отдельная форма настройки параметров расширения |
| `TL_ApiКлиент` | HTTP/JWT-клиент к STS API |
| `TL_Настройки` | Чтение и запись параметров расширения в регистр `TL_Настройки` |
| `TL_Маппинг` | Преобразование ключей и значений между API и объектами 1С |
| `TL_СозданиеДокументов` | Формирование документов 1С по данным смен и ТТН |
| `TL_HTMLГенератор` | Генерация HTML-представлений и UI-вставок для формы |
| `TL_РегистрСтатусов` | Хранение статусов обработки по ключам вида `TL|СМЕНА|...` и `TL|ТТН|...` |

## 5. Поток обработки

### Сменный отчёт

1. `TL_Загрузка` получает список смен через `TL_ApiКлиент`.
2. Для выбранной смены загружается сменный отчёт.
3. `TL_СозданиеДокументов` формирует:
   - `Отчёт о розничных продажах` для наличных и эквайринга;
   - `Перемещение товаров` по безналичным/корпоративным каналам.
4. `TL_РегистрСтатусов` фиксирует результат обработки и связку с документами 1С.

### Поступления по ТТН

1. Для смены отдельно запрашиваются `receipts`.
2. По каждой ТТН строится цепочка:
   - `Поступление товаров и услуг`;
   - `Перемещение товаров`;
   - `Комплектация номенклатуры`.
3. Плотность и пересчёт тоннаж/литры берутся из данных ТТН и настроек маппинга.

## 6. Учётная модель

Базовые правила, на которые опирается модуль создания документов:
- `41.01` — оптовый контур в массе;
- `41.02` — розничный контур в литрах;
- `50.01` — наличные;
- `57.03` — эквайринг;
- отдельные виртуальные склады используются для карт, талонов и ведомостей;
- пересчёт из тонн в литры делается через `Комплектацию`, а не прямым перемещением.

Конкретный маппинг номенклатуры, складов, каналов оплаты и станций хранится в регистре `TL_Настройки`.

## 8. Сборка и обновление

Актуальный сценарий сборки:
1. правим модули в `src/`;
2. `scripts/build.ps1` копирует `TL_*` в `xml-v4/`;
3. `1cv8 DESIGNER` загружает `xml-v4/` в расширение `TradeLedger`;
4. результат сохраняется как `build/TradeLedger.cfe`.

Вспомогательные скрипты:
- `scripts/update_gig.ps1` работает с `xml-v4/`;
- `scripts/export_update_import.ps1` оставлен как совместимый wrapper на `update_gig.ps1`.
