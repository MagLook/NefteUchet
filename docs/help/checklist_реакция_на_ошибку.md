# Чек-лист: Реакция на ошибку загрузки

Выполняется при каждой записи в регистре TL_ОшибкиЗагрузки с критичной категорией, а также при статусах пакета «ПринятоЧастично» или «Отклонено» в TL_СверкаПакета.

## Шаг 1. Идентификация

- [ ] В форме «Загрузка из STS» нажать **«Подробный отчёт ошибок»**.
- [ ] Отчёт открывается во весь экран с группировкой по категориям.
- [ ] Для каждой категории зафиксировать:
  - Сколько ошибок в категории (счётчик в шапке).
  - Время первой и последней ошибки.
  - Какие пакеты (колонка «Пакет») и какие значения (колонка «Значение»).

## Шаг 2. Классификация по категории

См. [gloss_коды_ошибок](gloss_коды_ошибок.md) — полный список 12 категорий.

- [ ] **STS_ОшибкаСервера** (HTTP 5xx):
  - Не настройка БП — серверная проблема STS.
  - Подождать 15-30 минут, повторить загрузку.
  - Если повторяется — обратиться в техподдержку pos.autooplata.ru с номером смены.

- [ ] **STS_ОшибкаАвторизации** (HTTP 401/403):
  - Проверить логин и пароль в **TradeLedger → Настройки расширения** → раздел Подключение.
  - Возможно истёк срок токена API — обратиться к обслуживающей организации.

- [ ] **STS_ОшибкаСети**:
  - Проверить подключение к интернету и VPN на сервере 1С.
  - После восстановления — «Перезагрузить период» → «Дозагрузить».

- [ ] **МаппингОплат_НеНайден**:
  - В STS появился новый pay_type — нужно завести запись в маппинге.
  - Открыть **TradeLedger → Маппинг видов оплат STS** → создать запись.
  - В поле «Образец имени» — кусок имени из колонки «Значение» в отчёте.
  - В поле «Канал» — выбрать подходящий (cards / online / ledger / voucher / retail_cash / retail_card / writeoff_fuel).
  - После заведения — «Перезагрузить период» → «Дозагрузить» для смен где была эта ошибка.

- [ ] **НСИ_НеНайдена**:
  - Контрагент → см. [faq_неизвестный_контрагент](faq_неизвестный_контрагент.md), создать карточку.
  - Номенклатура → создать карточку в БП ГИГ (Справочники → Номенклатура).
  - Склад / Подразделение / Организация → проверить и поправить настройки обмена.

- [ ] **ОбязательноеПолеПусто**:
  - В пакете нет обязательного значения (например, цена, дата, контрагент).
  - Сообщить центральной базе — оператору переформировать пакет.
  - После переформирования — «Перезагрузить период» → «Дозагрузить».

- [ ] **СтавкаНДС_НеСопоставлена**:
  - В пакете пришла неизвестная ставка НДС.
  - Сообщить разработчику расширения с указанием значения.

- [ ] **СчётУчёта_НеОпределён**:
  - В карточке номенклатуры или учётной политике не задан счёт учёта.
  - Открыть товар и заполнить вкладку «Счета учёта»: 41.02 для розницы.

- [ ] **СуммаНеСходится**:
  - Сумма в шапке документа не равна сумме строк.
  - Проверить пакет в центральной базе.

- [ ] **ВидОперацииНеСопоставлен**:
  - Источник прислал вид операции, не покрытый связкой.
  - Передать код вида операции (из колонки «Значение») разработчику расширения.

- [ ] **ОшибкаПроведения**:
  - Документ создан, но не провёлся.
  - Открыть документ через колонку «Пакет» в журнале сверки.
  - Нажать «Провести» вручную в БП, прочитать сообщение.
  - Устранить причину (счета учёта, остатки, обязательные реквизиты).

- [ ] **Прочее**:
  - Не разбираться самостоятельно.
  - Сделать скриншот формы с ошибкой.
  - Передать обслуживающей организации.

## Шаг 3. Применение исправления

- [ ] После правки в БП ГИГ (создан контрагент, поправлена номенклатура и т.п.):
  - Нажать **«Перезагрузить период»** → выбрать **«Да» (Дозагрузить)**.
  - Будут созданы только недостающие документы, дубли невозможны.
  - Дождаться завершения, прочитать журнал.
  - Обновить «Подробный отчёт ошибок» — ошибка пропала.

- [ ] После правки в центральной базе (переформирован пакет):
  - Дождаться переформирования (обычно несколько минут).
  - В форме «Загрузка из STS» нажать «Опросить каталог» — увидеть обновлённый файл.
  - **«Перезагрузить период»** → **«Да» (Дозагрузить)** — загрузить недостающее.

## Шаг 4. Контроль результата

- [ ] Открыть **TradeLedger → Сверка пакетов с источником**.
- [ ] Найти пакет — статус должен стать «ПринятоЦеликом».
- [ ] Колонка «Документов в БП» соответствует количеству ожидаемых.
- [ ] Расхождение нулевое или объяснимое (зафиксировать в комментарии).

## Шаг 5. Фиксация в журнале

- [ ] Записать в свой журнал: «Пакет UUID — категория X — устранено через Y — статус принято целиком».
- [ ] Если ошибка повторяющаяся — отметить для эскалации обслуживающей организации.
