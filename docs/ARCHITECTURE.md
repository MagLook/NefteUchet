# НефтеУчёт — Архитектура и решения

> **Дата:** 2026-03-20
> **Статус:** Зафиксировано, начинаем реализацию

---

## 1. Что делаем и почему

### Задача
Расширение (.cfe) для 1С:БП 3.0, которое автоматизирует ежедневную работу бухгалтера сети АЗС:
вместо ручного создания 5-6 документов на каждую смену — одна кнопка.

### Почему расширение, а не внешняя обработка (.epf)
- Расширение встраивается в конфигурацию — свои справочники, регистры, подсистема
- Сохраняется при обновлении типовой конфигурации
- Можно добавлять реквизиты к существующим объектам
- Профессиональнее для продукта (ClearLedger — продуктовый подход)

### Почему API напрямую из 1С, а не через промежуточный сервер
- API STS уже работает, TradeFrame его использует — проверенный путь
- Меньше точек отказа (1С → API, без посредников)
- В будущем можно переключить на ClearLedger API (тот же формат)

## 2. Источник данных

### API STS (pos.autooplata.ru/tms)

**Авторизация:** `POST /v2/login` (JWT, живёт 20 минут, обновлять через 18)

**Сменный отчёт:** `GET /v1/report/shift_report?system=&station=&shift=`
Содержит:
- `psm.data[]` — показания ТРК (pump, nozzle, volume, price, density)
- `release[]` — резервуары (tank, volume начало/конец, receipts, sales)
- `receipt[]` — поступления ТТН (ttn, поставщик, doc/fact объём/масса/плотность)
- `sales[]` — **продажи по видам оплаты** (наличные/карты/топл.карты → по видам топлива)
- `money[]` — кассовые операции

**Список смен:** `GET /v1/shifts?system=&station=&dt_beg=&dt_end=`

**System ID сетей:**
- БТО = 15 (тестовая)
- ГИГ = 65 (production)
- Энтиком = 29

## 3. Схема учёта

### Счета
- **41.01** — оптовый (тонны/кг)
- **41.02** — розничный (литры)
- **50.01** — касса (наличные)
- **57.03** — эквайринг (карты)
- **62** — расчёты с покупателями (топл.карты, ведомости)
- **60** — расчёты с поставщиками
- **90.01.1** — выручка, **90.02.1** — себестоимость, **90.03** — НДС
- **19** — входящий НДС, **68.02** — НДС к уплате

### Пересчёт тонны → литры
**Документ:** Комплектация номенклатуры (не Перемещение!)
- Комплектующие: «АИ-92 (т)» — X кг, счёт 41.01
- Комплект: «АИ-92 (л)» — X/ρ литров, счёт 41.02
- Плотность (ρ) из ТТН на уровне партии

### Виртуальные склады (обратный поток)
- Склад **«Карты»** → ежемесячная реализация БАЛТОП
- Склад **«Талоны»** → ежемесячная реализация БАЛТОП
- Склад **«Ведомости»** → корпоративные клиенты

## 4. Документы, создаваемые расширением

### Из сменного отчёта (ежедневно)

| Документ 1С | Данные из API | Проводки |
|-------------|--------------|----------|
| Отчёт о розничных продажах | `sales[]` наличные + карты | Дт 50.01/57.03 Кт 90.01.1 |
| Перемещение → Карты | `sales[]` топливные карты | Дт 41.02(Карты) Кт 41.02(АЗС) |
| Перемещение → Талоны | `sales[]` талоны/купоны | Дт 41.02(Талоны) Кт 41.02(АЗС) |
| Перемещение → Ведомости | `sales[]` корпоративные | Дт 41.02(Вед.) Кт 41.02(АЗС) |

### Из поступления ТТН

| Документ 1С | Данные из API | Проводки |
|-------------|--------------|----------|
| Поступление товаров | `receipt[]` doc.amount, doc.cost | Дт 41.01 Кт 60 + Дт 19 Кт 60 |
| Перемещение на АЗС | receipt → station | Дт 41.01(АЗС) Кт 41.01(осн.) |
| Комплектация | receipt.doc.density | Дт 41.02 Кт 41.01 |

## 5. Маппинг API → 1С

### Виды оплаты (sales[].pay_type)

| pay_type.name в API | Склад/счёт в 1С | Документ |
|--------------------|--------------------|----------|
| Наличные | — (прямая реализация) | Отчёт о розн. продажах, Дт 50.01 |
| Карты | — (прямая реализация) | Отчёт о розн. продажах, Дт 57.03 |
| Мобил / Безнал | — (прямая реализация) | Отчёт о розн. продажах, Дт 57.03 |
| Топливные карты | Склад «Карты» | Перемещение |
| Корпоративные (КР) | Склад «Ведомости» | Перемещение |

### Виды топлива (service.service_code)

| service_code | service_name | Номенклатура 1С (т) | Номенклатура 1С (л) |
|-------------|-------------|--------------------|--------------------|
| 92 | АИ-92 | АИ-92 (т) | АИ-92 (л) |
| 95 | АИ-95 | АИ-95 (т) | АИ-95 (л) |
| 98 | АИ-98 | АИ-98 (т) | АИ-98 (л) |
| 5 (DT) | ДТ | ДТ (т) | ДТ (л) |

Маппинг настраивается в регистре НУ_Настройки при установке.

### Что НЕ входит в MVP
- Справочники НУ_АЗС, НУ_ВидыТоплива (пока через регистр настроек)
- Документы НУ_СменныйОтчёт, НУ_ПриходТоплива (пока не храним, сразу создаём)
- Трёхсторонняя сверка (будет в ClearLedger)
- AI-аудит (будет в TSupport)

## 7. Разработка

### Инструменты
- **VS Code** + BSL Language Server (подсветка, линтинг)
- **Git** (этот репо: MagLook/NefteUchet)
- **PowerShell** скрипт сборки (xml → .cfe)
- **1cv8.exe DESIGNER** для компиляции

### Структура репо
```
NefteUchet/
├── src/                        # .bsl модули (исходный код)
│   ├── CommonModules/
│   │   ├── НУ_ApiКлиент.bsl
│   │   └── НУ_СозданиеДокументов.bsl
│   └── DataProcessors/
│       └── НУ_Загрузка/
│           └── Forms/
│               └── Форма/
│                   └── Module.bsl
├── xml/                        # XML-выгрузка расширения (для 1cv8 DESIGNER)
├── scripts/
│   └── build.ps1               # Сборка .cfe
├── docs/
│   └── ARCHITECTURE.md         # Этот файл
├── build/                      # .cfe файлы (в .gitignore)
├── CLAUDE.md
└── README.md
```

### Процесс сборки
```
1. Редактируем .bsl в VS Code
2. Копируем в xml/ (структура расширения)
3. scripts/build.ps1:
   - 1cv8.exe DESIGNER /LoadConfigFromFiles xml/ -Extension НУ_НефтеУчёт
   - 1cv8.exe DESIGNER /DumpCfg build/НефтеУчёт.cfe -Extension НУ_НефтеУчёт
4. Результат: build/НефтеУчёт.cfe → бухгалтеру
```

## 8. Порядок реализации

### Шаг 1: НУ_ApiКлиент.bsl
- ПолучитьТокен(URL, Логин, Пароль) → JWT
- ВыполнитьЗапрос(Метод, Путь, Параметры) → JSON
- ПолучитьСписокСмен(Система, Станция, ДатаНач, ДатаКон) → Массив
- ПолучитьСменныйОтчёт(Система, Станция, НомерСмены) → Структура
- ПолучитьПоступления(Система, Станция, НомерСмены) → Массив

### Шаг 2: НУ_СозданиеДокументов.bsl
- СоздатьРозничныеПродажи(ДанныеСмены, Настройки) → Документ
- СоздатьПеремещение(ДанныеСмены, ВидОплаты, Настройки) → Документ
- СоздатьПоступление(ДанныеТТН, Настройки) → Документ
- СоздатьКомплектацию(ДанныеТТН, Плотность, Настройки) → Документ

### Шаг 3: НУ_Загрузка (форма)
- Кнопка «Загрузить» → API → таблица на форме
- Кнопка «Создать документы» → НУ_СозданиеДокументов
- Кнопка «Провести» → документы проводятся
- Лог операций внизу формы

### Шаг 4: Тест
- Учебная база 1С:БП 3.0
- Реальные данные из API (система 15, станция 4)
- Сравнение проводок с ручным проведением

## 9. Связь с экосистемой ClearLedger

### Сейчас (MVP)
Расширение работает НАПРЯМУЮ с API STS. Минимум зависимостей.

### Потом (эволюция)
```
MVP:   1С ←→ API STS (напрямую)
v2:    1С ←→ ClearLedger API ←→ API STS (через платформу)
v3:    1С ←→ ClearLedger API ←→ множество источников + AI-сверка
```

Переход на ClearLedger API — замена URL и формата ответа в НУ_ApiКлиент.
Архитектура расширения не меняется.
