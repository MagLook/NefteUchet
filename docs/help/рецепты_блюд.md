# Рецепты блюд (ТТК)

Для работы общепита по новой схеме (см. [общепит_что_изменилось](общепит_что_изменилось.md)) в БП ГИГ нужны рецепты блюд — что входит в Эспрессо, Капучино, Хот-дог и т.д.

## Где хранятся рецепты в БП ГИГ

В справочнике **«Спецификации номенклатуры»** (стандартный объект 1С). Каждый рецепт — это элемент справочника с привязкой к блюду:

| Реквизит | Содержит |
|---|---|
| Владелец | Блюдо (например «Эспрессо 60мл») из справочника Номенклатура |
| Наименование | «ТТК Эспрессо 60мл» |
| Активна | Да (если рецепт действующий) |
| Исходные комплектующие | Табличная часть с ингредиентами |

В табличной части — строки с ингредиентами:

| Номенклатура | Количество |
|---|---:|
| Кофе зерно | 9 г |
| Вода | 60 мл |
| Стакан 60 мл | 1 шт |

## Откуда берутся рецепты

Рецепты заполняются **автоматически** из центральной базы ЭЛСИ.АЗК — никаких ручных действий бухгалтера. Технолог в центральной базе создаёт или изменяет ТТК → изменение приходит в БП ГИГ в течение нескольких минут.

### Технически: как работает синхронизация

1. **Технолог в центральной базе** меняет ТТК «Капучино» — добавляет молоко 100 мл к существующим кофе и стакану.
2. **При сохранении** документа ТТК в центральной базе расширение TL_ЭкспортБП (другое расширение, в центральной базе) формирует JSON-пакет с типом `recipe`.
3. **Файл tl_recipe_*.json** попадает в каталог обмена (OwnCloud).
4. **БП ГИГ при следующей загрузке** обрабатывает пакет: находит «Капучино» по уникальному коду, находит/создаёт его СпецификациюНоменклатуры, очищает старый состав, заполняет новым (с молоком).
5. **С этого момента** при продаже Капучино в Комплектации молоко тоже будет списываться.

### Зачем такая сложность

Это позволяет:
- **Не дублировать ввод** — технолог пишет рецепт один раз в ЦБ, в БП ГИГ он появляется сам.
- **Сразу применять изменения** — поменяли рецепт в обед, в вечернюю смену уже работает по-новому.
- **Не путать версии** — единый источник истины в ЦБ, БП ГИГ всегда синхронизирована.

## Что делать бухгалтеру если рецепт неактуальный

Если бухгалтер видит что в БП ГИГ ТТК Капучино старая (без молока, например), а должна быть новая:

1. **Не правьте вручную** в БП ГИГ. Ваши правки перетрутся при следующей синхронизации.
2. Сообщите технологу центральной базы что рецепт устарел.
3. Технолог обновит ТТК в ЦБ.
4. После следующей загрузки пакета — рецепт в БП ГИГ обновится сам.

## Что делать если блюдо новое и рецепта ещё нет

Расширение начинает учитывать блюдо только когда:
1. Появилось в Справочнике Номенклатура (приходит автоматически при первой продаже или из центральной базы).
2. Появилась активная СпецификацияНоменклатуры с ингредиентами.

Если **рецепта нет** на момент продажи:
- Блюдо обработается **как товар** — пройдёт через ОРП одной строкой с Дт 90.02.1 / Кт 41.02 на это блюдо.
- В журнале появится **предупреждение**: «Блюдо «Капучино» не раскрыто — нет рецепта».
- В подробном отчёте ошибок будет категория НСИ_НеНайдена.

**Решение:**
1. Дождаться синхронизации ТТК из ЦБ.
2. После появления СпецификацииНоменклатуры — открыть форму «Загрузка из STS» → нажать **«Перезагрузить период»** → **«Да» (Дозагрузить)** для затронутого периода. Расширение создаст недостающую Комплектацию (ОРП остаётся блюдо-одной-строкой).

## Где посмотреть какие рецепты сейчас есть

В БП ГИГ:
- Главное меню → **Все функции...** → Справочники → **Спецификации номенклатуры**.
- Откроется список всех рецептов с группировкой по Владельцу (блюду).

## Что если рецепт изменили — старые ОРП пересчитывать?

**Нет.** Старые ОРП остаются с тем рецептом который был на момент создания. Пересчёт не делается. Это бухгалтерский стандарт — после закрытия отчётного периода первичные документы не меняются ретроспективно.
