# FAQ: Дубль пакета. Идемпотентность

При повторной загрузке одного и того же пакета документы в БП **не дублируются**. Это контролируется регистрами **TL_СоответствиеИсточников** (сопутка/общепит) и **TL_СтатусыЗагрузки** (топливо STS).

## Как работает идемпотентность

Каждый внешний объект (документ, элемент справочника, ПКО) в центральной базе имеет уникальный UUID. При обработке пакета:

1. Для каждого объекта вычисляется ключ: `ИсточникUUID` + `Тип`.
2. По этому ключу ищется запись в TL_СоответствиеИсточников.
3. Если запись есть — берётся существующая ссылка на документ в БП, обновляется содержимое (если изменилось).
4. Если записи нет — создаётся новый документ в БП, и в регистр пишется новая запись.

Для топлива STS: ключ = `TL|СМЕНА|sysid|station|num`. Регистр TL_СтатусыЗагрузки хранит маркер «уже загружено». Повторная загрузка проверяет наличие записи и пропускает.

Дополнительно: для каждого пакета сохраняется хеш содержимого (`ХешПоследнегоПакета`). При повторной загрузке пакета с тем же UUID:
- Если хеш совпадает с предыдущим — обработка пропускается (нет смысла).
- Если хеш изменился — пакет переобрабатывается, документы обновляются.

## Что увидеть в форме

При повторной загрузке в TL_СверкаПакета появляется новая запись (или обновляется существующая) с тем же ИдентификаторПакета. Можно посмотреть историю загрузок одного пакета через стандартный список регистра TL_СверкаПакета без фильтра.

## Когда дубль всё-таки возможен

### 1. Документ удалён вручную, регистр не очищен

Документ был удалён вручную в БП ГИГ через журнал, но запись в TL_СоответствиеИсточников / TL_СтатусыЗагрузки осталась. При следующей загрузке создаётся новая ссылка → запись в регистре обновляется на новую → формально дубля нет, но старая ссылка становится «битой».

- Действие: использовать кнопку **«Сбросить регистрацию»** в форме «Загрузка из STS» (в подменю «Ещё»). Для выбранного периода она удаляет записи из TL_СтатусыЗагрузки (документы БП не трогает). После сброса повторная загрузка создаст документ заново.

### 2. Документ создан вручную в БП

Документ создан вручную в БП ГИГ напрямую (без приёма пакета). Затем приходит пакет с этим же содержимым — создаётся ещё один документ.

- Действие: при ручном создании документов по приёму пакетов проверять что пакет уже не приходил. Лучше не создавать вручную то, что обычно приходит автоматически.

### 3. Два разных пакета с одинаковым содержимым

Например ошибка в центральной базе — один и тот же документ выгружен в двух пакетах с разными UUID.

- Действие: устранить в центральной базе, удалить лишний документ в БП ГИГ вручную.
