# Последние документы — журнал созданных расширением

Команда **«Последние документы»** в меню «Ещё» формы «Загрузка из STS» открывает список регистра **TL_СоответствиеИсточников** — все документы которые расширение когда-либо создало.

## Зачем нужно

- Найти конкретный документ по уникальному коду из ошибки.
- Посмотреть когда расширение последний раз обновляло документ.
- Открыть документ в БП одним кликом.
- Проверить какие документы привязаны к конкретному пакету.

## Что показывает

| Колонка | Содержит |
|---|---|
| Тип | Тип объекта (Поступление / ОтчётОРозничныхПродажах / ПКО / Перемещение / Списание / СпецификацияНоменклатуры …) |
| ИсточникUUID | Уникальный код элемента в центральной базе |
| Ссылка | Ссылка на документ или элемент справочника в БП ГИГ |
| ДатаПоследнейЗагрузки | Когда расширение последний раз обновило |
| ИдентификаторПоследнегоПакета | Пакет в котором документ был обновлён |
| ХешПоследнегоПакета | Контрольная сумма пакета (для идемпотентности) |

## Как пользоваться

### Открыть документ

Двойной клик по колонке **Ссылка** → откроется стандартная форма документа БП.

В открытом документе можно нажать **Дт/Кт** и посмотреть проводки.

### Найти документ по уникальному коду

Если в подробном отчёте ошибок есть код вида `7c3a9e85-...`:
1. Открыть «Последние документы».
2. Скопировать код из ошибки.
3. В колонке ИсточникUUID найти строку (Ctrl+F).
4. Двойной клик — документ откроется.

### Фильтр по типу

Стандартные средства списка регистра:
- Кнопка «Настроить список».
- Условие: Тип = «Поступление».
- Применить.

Видно только ПТУ. Аналогично для других типов.

### Фильтр по пакету

Если нужно увидеть все документы конкретного пакета:
1. Открыть **TradeLedger → Сверка пакетов с источником**.
2. Найти пакет.
3. Кнопка **«Документы пакета»** — откроет список с фильтром автоматически.

## Зачем поле «Хеш последнего пакета»

Это контрольная сумма содержимого пакета. Используется для **идемпотентности**:
- Если пакет приходит повторно с тем же содержимым (хеш совпадает) — расширение видит «уже обрабатывали такое» и пропускает.
- Если хеш изменился — пакет переобрабатывается, документы обновляются.

Бухгалтеру с хешем работать не нужно — это служебное поле.

## Если документ удалён вручную в БП

Удалили документ через помеченные → удалённые, но запись в регистре осталась:
- В колонке Ссылка будет «битая ссылка» или ошибка при открытии.
- При следующей загрузке расширение создаст документ заново и обновит запись.

Если нужно полностью очистить запись — см. [перезагрузить_период](перезагрузить_период.md) → раздел «Сбросить регистрацию».
