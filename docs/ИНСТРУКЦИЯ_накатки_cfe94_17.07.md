# Накатка cfe94 — ПКО на наличную выручку сопутки (кассовые документы)

Дата подготовки: 17.07.2026. Накатывает МАГ вручную. Основание — письмо Ирины:
«В кассовые документы не попадает выручка (наличн) по сопутв.товарам. В июне завела вручную».

## Проблема (подтверждена на боевой)

Канал **сопутки** (ЦБ → `TL_СопуткаСервис`) создавал ОРП, но **не создавал ПКО**
(Поступление наличных, КО-1). Наличные оседали только проводкой Дт 50.01 Кт 62.Р
из самого ОРП, а кассового документа не было → в кассовую книгу выручка не попадала.
Канал **топлива** (STS → `TL_СозданиеДокументов`) ПКО создавал всегда — отсюда асимметрия.

Факт по 208 (probe 17.07, `scripts/_out_pko_kassa.txt`, `_out_pko_208_detail.txt`):

| Период | ОРП сопутки | Наличные | Кассовый документ |
|---|---|---|---|
| 11.06–30.06 | 23 | 173 840 ₽ | заведены **вручную** Ириной (ГИ0Г-001695…001717), суммы совпадают копейка в копейку |
| 01.07–07.07 | 7 | **103 585 ₽** | **отсутствуют** |

ПКО «Розничная выручка» в БП 3.0 **проводок не делает** (проверено: 421 ПКО расширения +
179 ручных ПКО бухгалтерии = 0 движений). Поэтому правка **на учёт не влияет** —
закрывает только кассовую книгу и печать КО-1.

## Что входит (2 модуля)

| Модуль | Правка |
|---|---|
| `TL_СозданиеДокументов` | Ядро `СоздатьПКОПоОРП` вынесено в **экспортную функцию** (заполнение + запись ПКО, без привязки к реестру). Топливная `СоздатьПКО` стала обёрткой: зовёт ядро + пишет свой реестр `TL_РегистрСтатусов`. **Поведение топлива не меняется** |
| `TL_СопуткаСервис` | Новое: `СоздатьПКОСопутки` (вызов в конце `ОбработатьRetailSale`), `НайтиРучнойПКОСмены` (гейт), `АннулироватьПКОСопутки` (каскад). Регистрация в `TL_СоответствиеИсточников` типом **ПКО** |

Ключевые решения в коде:

- **Наличные = СуммаДокумента − Σ(ТЧ Оплата)** (в ТЧ Оплата только безнал).
  Формула сверена с проводками Дт 50.01 на 30 ОРП 208 — сходится копейка в копейку.
- **ПКО создаётся ПОСЛЕ фиксации транзакции ОРП** — он вторичен и не должен ронять смену.
- **Гейт ручного ПКО**: если бухгалтер уже завёл ордер за тот же склад+день+сумму
  (ручной опознаётся по отсутствию `TL|` в комментарии) — авто-ПКО **не создаётся**,
  в ЖР пишется информационная запись. Без гейта перезагрузка июня удвоила бы
  приход в кассовой книге (проводок нет, но документы удвоились бы).
- **Идемпотентность** — через реестр `(Тип=ПКО, ИсточникUUID)`.
- **Каскад**: аннулирование ОРП помечает и его ПКО (иначе аннулированная выручка
  осталась бы живым приходом в кассе). «Зачистить аннулированные» ПКО уже
  подхватывает — `ПриходныйКассовыйОрдер` есть в списке типов канала.

## Порядок

1. Резерв: выгрузить текущее боевое расширение (Конфигуратор → Расширения →
   TradeLedger → Сохранить как .cfe).
2. Загрузить конфигурацию расширения из `xml-v4/` (src и xml-v4 синхронны).
3. F7 не требуется — изменены только модули, метаданные не трогали
   (значение `ПКО` в перечислении `TL_ТипОбъектаИсточника` уже существовало).
4. **Обязательно: Проверка модулей (/CheckModules)** — общие модули компилируются лениво.

## Smoke после наката

1. Загрузить одну смену сопутки 208 (например 08.07 из `C:\TL_BP_Export`) формой TL_Загрузка.
2. Проверить, что вместе с ОРП создан **Поступление наличных**:
   - сумма = наличные смены (СуммаДок − безнал);
   - вид операции «Розничная выручка», Склад = АЗС Выборг (208);
   - Документ-основание = наш ОРП; комментарий оканчивается на `|ПКО`;
   - **движений нет** (это норма).
3. Документ виден в разделе «Банк и касса → Кассовые документы» и печатается как КО-1.
4. Повторная загрузка той же смены → второй ПКО **не создаётся** (реестр).
5. В ЖР не должно быть ошибок `TL_СопуткаСервис.ПКО`.

## Июль 01–07.07 (103 585 ₽) — отдельно, скриптом

`scripts/_fix_pko_july_208.py` — доначисляет 7 ПКО за уже загруженные смены
(перезагружать их не нужно). Идемпотентен целиком: пропускает смену, если ПКО уже
в реестре либо в базе есть непомеченный ордер с тем же складом/днём/суммой.

    python _fix_pko_july_208.py            # DRY-RUN
    python _fix_pko_july_208.py --apply    # запись в боевую

Скрипт ставит тот же комментарий (`…|ПКО`) и пишет запись реестра — поэтому
после наката перезагрузка июля дублей не даст.

**Июнь не трогаем**: там ручные ПКО Ирины, суммы верные, гейт их защищает.
