# Что делать когда увидели ошибку — пошагово

Сценарий применяется при каждом появлении ошибки в подробном отчёте, в журнале ошибок или при жёлтой/красной строке в сверке пакетов.

## Шаг 1. Зафиксировать что произошло

1. В форме **«Загрузка из STS»** нажать **«Подробный отчёт ошибок»**.
2. В открывшемся окне — какие категории ошибок есть. Цвет и иконка сразу намекают:
   - 🟡 Жёлтый = ждать, не срочно (серверы STS).
   - 🔴 Красный = срочно (авторизация, проведение).
   - 🔵 Синий = сеть.
   - 🟣 Фиолетовый = настройка маппинга.
   - 🩵 Бирюзовый = справочники / реквизиты.
   - ❓ Серый = редкое.

3. Для каждой категории зафиксировать:
   - Сколько ошибок.
   - Когда первая и последняя.
   - Какие пакеты и значения.

## Шаг 2. Прочитать «Что делать»

В каждой группе ошибок есть блок **«Что делать»** — короткая инструкция.

Если непонятно или нужно подробнее — клик **«📖 Подробнее»** → откроется статья в новом окне.

## Шаг 3. Выбрать сценарий по категории

### Серверная ошибка STS (🟡 STS_ОшибкаСервера)

Это не настройка БП — сервер pos.autooplata.ru не отдал данные.

1. Подождать 15-30 минут.
2. В форме «Загрузка из STS» нажать «Обновить» — попробовать снова.
3. Если повторяется > 1 часа — позвонить в техподдержку pos.autooplata.ru.

### Ошибка авторизации STS (🔴 STS_ОшибкаАвторизации)

1. Открыть **TradeLedger → Настройки расширения**.
2. Раздел «Подключение».
3. Проверить логин и пароль.
4. Если правильные — обратиться в обслуживающую организацию (возможно нужно обновить токен).

### Ошибка сети (🔵 STS_ОшибкаСети)

1. Проверить интернет на сервере 1С.
2. Если используется VPN — проверить что VPN включен.
3. После восстановления — «Перезагрузить период» → «Да».

### Маппинг оплат не найден (🟣 МаппингОплат_НеНайден)

В смене встретился вид оплаты которого расширение не знает.

1. Посмотреть в колонке «Значение» — какое имя пришло.
2. Открыть **TradeLedger → Маппинг видов оплат STS**.
3. Создать новую запись:
   - Образец имени: часть имени из ошибки (например «газпромнефть»)
   - Канал: cards / online / ledger / voucher / retail_cash / retail_card / writeoff_fuel
4. После заведения — в форме «Загрузка из STS» нажать **«Перезагрузить период»** → **«Да» (Дозагрузить)**.

### НСИ не найдена (🩵 НСИ_НеНайдена)

Не найден контрагент / номенклатура / склад / организация / подразделение.

- **Контрагент** → см. [неизвестный_контрагент](неизвестный_контрагент.md).
- **Номенклатура** → создать в БП ГИГ (Справочники → Номенклатура).
- **Склад / Организация / Подразделение** → проверить настройки обмена.

После создания — «Перезагрузить период» → «Да» (Дозагрузить).

### Ставка НДС не сопоставлена (🩵 СтавкаНДС_НеСопоставлена)

Сообщить обслуживающей организации какое значение пришло (из колонки «Значение»).

### Счёт учёта не определён (🩵 СчётУчёта_НеОпределён)

В карточке номенклатуры нет счёта учёта.

1. Открыть карточку товара.
2. Вкладка «Счета учёта».
3. Задать 41.02 для розницы.

### Обязательное поле пусто (🩵 ОбязательноеПолеПусто)

Источник не передал важное значение (цена, дата, контрагент).

1. Сообщить в центральную базу.
2. Оператор переформирует пакет.
3. «Перезагрузить период» → «Да».

### Ошибка проведения (🔴 ОшибкаПроведения)

Документ создан, но БП ругается при проведении.

1. Открыть документ через сверку пакетов или журнал БП.
2. Нажать «Провести» вручную.
3. Прочитать сообщение БП — обычно понятное.
4. Устранить (восполнить остаток, заполнить реквизит).

### Сумма не сходится (🔴 СуммаНеСходится)

Сумма шапки документа ≠ сумма строк. Ошибка в исходных данных.

1. Сообщить в центральную базу.
2. Оператор переформирует.

### Вид операции не сопоставлен (🟣 ВидОперацииНеСопоставлен)

Источник прислал неизвестный вид операции. Сообщить разработчику (через обслуживающую организацию).

### Прочее (❓ Прочее)

Не разбираться самостоятельно. Скриншот + сообщение в обслуживающую организацию.

## Шаг 4. Применить «Перезагрузить период»

После устранения причины (в БП или в центральной базе):

1. В форме «Загрузка из STS» нажать **«Перезагрузить период»**.
2. Указать период когда была ошибка.
3. Выбрать **«Да» (Дозагрузить)** — создаст недостающее. Дубли невозможны.
4. Дождаться завершения.

## Шаг 5. Проверить что ошибка исчезла

1. Снова открыть «Подробный отчёт ошибок».
2. Категория должна исчезнуть или количество уменьшиться.
3. Если осталась — повторить с другой причиной.

## Шаг 6. Зафиксировать в журнале

Записать в свой бумажный/электронный журнал: «Дата — пакет X — категория Y — устранено через Z».

Если ошибка повторяющаяся (одна и та же ситуация второй раз) — отметить для эскалации обслуживающей организации.
