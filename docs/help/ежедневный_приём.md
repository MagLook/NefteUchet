# Ежедневный приём данных с АЗС

Главный сценарий работы бухгалтера. Выполняется каждое утро (для вчерашних смен) и при необходимости в течение дня (для текущих).

## Утренний приём — занимает 5-10 минут

### Шаг 1. Открыть форму

**TradeLedger → Загрузка из STS (топливо)**

### Шаг 2. Поставить период

В полях периода:
- **Дата начала**: вчера (или с понедельника текущей недели если опускали)
- **Дата окончания**: сегодня

### Шаг 3. Загрузить топливо

1. Убедиться что в меню «Ещё» режим «Нефтепродукты».
2. Нажать **«Обновить»** — справа в таблице появятся вчерашние смены.
3. Если смен нет — проверить лог слева. Возможно ошибка авторизации или связи с STS (см. [категории_ошибок](категории_ошибок.md) → STS).
4. Кнопка **«Выбрать все»** над правой таблицей → отметятся все строки.
5. Кнопка **«◀ Загрузить выбранные»** → начнётся загрузка.
6. Дождаться окончания (видно по логу слева).

После загрузки в БП появятся:
- Отчёты о розничных продажах за каждую смену.
- Перемещения на виртуальные склады (карты, талоны, ведомости).
- ПКО на сумму наличных.
- Документы СписаниеТоваров для технических списаний (см. [техсписания_топлива](техсписания_топлива.md)).

### Шаг 4. Загрузить сопутку

1. В меню «Ещё» переключить режим на **«Сопутка»**.
2. В том же меню «Ещё» нажать **«Опросить каталог»** — расширение посмотрит папку обмена, скажет сколько новых файлов.
3. **«Обновить»** → справа появятся пакеты.
4. **«Выбрать все»** → **«◀ Загрузить выбранные»**.

После загрузки появятся ПТУ, ОРП, корректировки.

### Шаг 5. Загрузить общепит

1. В меню «Ещё» переключить режим на **«Общепит»**.
2. **«Опросить каталог»** → **«Обновить»** → **«Выбрать все»** → **«◀ Загрузить выбранные»**.

С новой моделью B (с 22.05.2026) ОПЗС больше не создаётся — общепит уходит в ОРП сопутки с раскладкой блюд по ингредиентам. См. [общепит_что_изменилось](общепит_что_изменилось.md).

### Шаг 6. Проверить ошибки

1. Кнопка **«Подробный отчёт ошибок»** — откроется отдельное окно.
2. Если ✓ Ошибок нет → закрыть, день пройден.
3. Если есть категории — каждую разобрать по инструкции [реакция_на_ошибку](реакция_на_ошибку.md).

### Шаг 7. Проверить сверку (опционально для контроля)

1. **TradeLedger → Сверка пакетов с источником**.
2. Период — вчера.
3. Все строки должны быть зелёные (ПринятоЦеликом).
4. Если есть жёлтые/красные — открыть «Показать ошибки пакета», разобрать.

## Дневной приём (текущие смены)

Если на АЗС идут оживлённые продажи — пакеты могут приходить в обед, в 18:00, ночью. Бухгалтер может загружать их по тому же сценарию по мере необходимости — расширение не плодит дубли.

Можно тоже сделать через **«Перезагрузить период»** → **«Да» (Дозагрузить)** — это безопасно, создаст только новое.

## Когда подключать обслуживающую организацию

- Ошибки категории **STS_ОшибкаСервера** идут больше часа.
- Ошибки **STS_ОшибкаАвторизации** — возможно нужно обновить токен.
- Расхождение в сверке > 100 ₽ на одном пакете несколько дней подряд.
- Систематические ошибки по одному поставщику или одной АЗС.
- Каталог OwnCloud недоступен (журнал сообщает).
- Появилась незнакомая ошибка в подробном отчёте, не описанная в [категории_ошибок](категории_ошибок.md).
