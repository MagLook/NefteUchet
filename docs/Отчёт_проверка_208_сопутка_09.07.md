## 5. Порядок проведения сопутки/общепита (по коду)

Проведение через форму TL_Загрузка, витрина «список дел». На каждую смену, **в одной транзакции**:

1. **Комплектации блюд** (`TL|ВЫПУСКБЛЮД|<UUID>`) — сборка из ингредиентов, партия на склад до продажи
2. **Основной документ** (ОРП) — `Записать(Проведение)`
3. **Разукомплектации** (`TL|РАЗБОРБЛЮД|<UUID>`) — разбор возвратов

Особенности:
- Двухфазность ПЕРЕМ→КОМПЛ — **только для топлива**, к сопутке не применяется.
- Витрина сортируется `Дата УБЫВ, КлючБазовый, ТипДокумента` — **строгого порядка «приход→расход» по типу нет**. Компенсируется оценкой МПЗ «По средней» (себестоимость считается при закрытии месяца по дате документа) + допустимостью отрицательных остатков.
- Инвентаризация сама остатки не двигает — приход/недостача идёт Оприходованием/Списанием.
- Строки «⚠ Изменён в ЦБ после проведения» автоматически пропускаются (решение бухгалтера).

**Суммы:** Опр. 156.84 / 80 / 208.15 / 2.40 / 229 ₽; Спис. 335 / 330 / 117 / 1344 / 750 / 1010 ₽.

### Корневая причина (доведена до конца)

- UUID `43fa052c-8834-11ed-ad72-002590317e3f` **не существует ни в одном из 105 справочников ЦБ** (проверено запросом + полным перебором). Это **висячая (битая) ссылка**.
- Источник — документ в самом ЦБ:
  `ИнвентаризацияТоваровНаСкладе №20800000075 от 10.06.2026 09:34:08` (ст. 208), строка: Номенклатура = **«Объект не найден»**, кол-во 1, сумма 936.36 ₽, класс SKU «Сопутка».
- Карточка номенклатуры была **физически удалена** из справочника ЦБ, а документ инвентаризации на неё ссылается. Экспорт протащил битую ссылку → пустая НСИ в пакете → в БП не сопоставилось → инвентаризация не обработалась → её Оприходования/Списания зависли.

**Это дефект данных в ЦБ, а не в коде расширения/пересинке.**

### Что мешает опознать товар
Наименование из ЦБ восстановить нельзя (элемент удалён). Опознать можно только извне:
- станция D:\208 — **недоступна с машины МАГ** (папки D:\208 нет, база на самой станции .121);
- касса .125 `dba.Tariffs` (станционная сеть);
