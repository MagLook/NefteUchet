# Проводки розничной продажи (сопутка)

kind пакета: **`retail_sale_sidegoods`**.

Создаётся документ **ОтчётОРозничныхПродажах** (ОРП) с видом операции **ОтчётККМОПродажах**.

## Проводки

Для каждой строки товара:

| Дебет | Кредит | Содержание |
|---|---|---|
| 90.02.1 | 41.02 | Себестоимость проданного товара (списание со склада) |
| 62.Р | 90.01.1 | Выручка от продажи (по продажной цене) |
| 90.03 | 68.02 | НДС с продажи |

Для табличной части «Расшифровка платежа» — одна проводка на каждый канал оплаты:

| Дебет | Кредит | Канал оплаты |
|---|---|---|
| 50.01 | 62.Р | Наличные в кассу |
| 57.03 | 62.Р | Эквайринг (банковская карта) |
| 76.АВ | 62.Р | Прочие безналичные (купоны, сертификаты) |

## Что формирует пакет

- Шапка ОРП: дата смены, организация (ГИГ), подразделение, склад.
- Табличная часть «Товары»: SKU, количество, цена продажи, цена закупки, ставка НДС.
- Табличная часть «Расшифровка платежа»: вид оплаты, сумма.

## Источник сумм

Все суммы — из данных кассового аппарата АЗС, переданных через центральную базу.

## Контроль

- Сумма по табличной части «Товары» должна совпадать с суммой по «Расшифровке платежа».
- Расхождение более 0.01 ₽ — попадает в TL_СверкаПакета как Расхождение.
- При расхождении следует проверить: правильно ли сформирован пакет в центральной базе, нет ли пропущенных строк.

## Типовые проблемы

- **Не найден вид оплаты** — настроить **TradeLedger → Настройки обмена сопутки** → поле «Вид оплаты безнал».
- **Не найдена номенклатура** — справочник Номенклатура в БП ГИГ не содержит элемент с переданным UUID. Создать вручную или через автомаппинг.
- **НДС не подтянулся** — проверить настройку «Ставка НДС» в карточке номенклатуры.
