# День X — перевод следующей АЗС на ГИГ

В сети идёт постепенный переход АЗС с прежней организации (Норд-Лайн) на ГАЗИНВЕСТГРУПП. Каждая АЗС переводится в свой «День X». Бухгалтер выполняет действия в БП ГИГ; параллельно товаровед — в центральной базе.

## Предусловия

- Согласован договор купли-продажи между прежней и новой организацией.
- Согласована точная дата и время Дня X.
- **Бэкап БП ГИГ сделан** до начала операции.
- В БП ГИГ заведено подразделение и склад для переводимой АЗС.
- В **TradeLedger → Настройки обмена сопутки** и **Настройки обмена общепита** проверены параметры (особенно склад и подразделение по новой АЗС).
- Маркируемые товары (Честный Знак) при переводе между АЗС одного ИНН выводить через MSN_ПеремещениеМеждуАЗС в центральной базе **до** Дня X.

## T − 1 час

- [ ] **TradeLedger → Сверка пакетов с источником** — проверить что нет «висящих» жёлтых/красных пакетов по этой АЗС.
- [ ] Если есть — устранить (см. [реакция_на_ошибку](реакция_на_ошибку.md)).
- [ ] **«Подробный отчёт ошибок»** — за сегодня не должно быть критичных ошибок по этой АЗС.
- [ ] Сообщить центральной базе: бухгалтерия готова к приёму Дня X.

## T (момент перевода)

Центральная база проводит документ MSN_ПередачаДняX — он формирует:
- Корректировку остатков регистра ТоварыОрганизаций (расход у Норд-Лайн, приход у ГИГ).
- РеализациюТоваровУслуг (Норд-Лайн → Контрагент-ГИГ).
- ПоступлениеТоваровУслугНаАЗК (Контрагент-Норд-Лайн → ГИГ) — пакет с типом «покупка» прилетает в БП ГИГ.

На АЗС оператор переключает основную организацию через RDP с Норд-Лайн на ГАЗИНВЕСТГРУПП.

## T + 5-10 минут

- [ ] В форме **«Загрузка из STS»** в меню «Ещё» → **«Опросить каталог»** → должен быть новый пакет переноса остатков.
- [ ] Загрузить пакет → создаётся ПТУ от контрагента-Норд-Лайн.
- [ ] Проверить документ:
  - Контрагент — Норд-Лайн как поставщик.
  - Договор — отдельный по передаче (или общий «прочие операции»).
  - Сумма — соответствует акту приёма-передачи.
  - Проводки — 41.02/60.01 + 19.03/60.01.
- [ ] Провести документ.

## T + 30 минут

- [ ] **TradeLedger → Сверка пакетов с источником**.
- [ ] Найти пакет передачи остатков.
- [ ] Проверить: статус «ПринятоЦеликом», расхождение = 0.
- [ ] Если расхождение есть — срочно разобрать до возобновления работы АЗС.

## T + 1 час

- [ ] Стандартный цикл приёма пакетов восстановлен.
- [ ] Форма «Загрузка из STS», переключить режим Сопутка/Общепит → должны приходить пакеты уже от ГАЗИНВЕСТГРУПП.
- [ ] Загрузить пакеты обычным способом.
- [ ] Проверить что новые записи в **TradeLedger → Последние документы** привязаны к новой организации.

## Период стабилизации (3-7 дней)

- [ ] Ежедневный приём — повышенное внимание к сверке.
- [ ] Сравнение остатков по 41.02 БП ГИГ с фактическими остатками АЗС.
- [ ] При обнаружении расхождений — корректировка через стандартные документы БП (Инвентаризация → Списание/Оприходование) с согласованием.
- [ ] Если появились ошибки маппинга оплат для новой АЗС — устранить через **TradeLedger → Маппинг видов оплат STS** + **«Перезагрузить период»** → **«Да» (Дозагрузить)**.

## Возврат назад (если что-то пошло не так)

- [ ] В центральной базе отменить проведение MSN_ПередачаДняX → автоматически откатятся регистры остатков и связанные документы.
- [ ] В БП ГИГ — отменить проведение и пометить на удаление принятые документы по этой передаче.
- [ ] Если связь с пакетами нужно очистить — использовать **«Сбросить регистрацию»** (в меню «Ещё» формы «Загрузка из STS») для затронутого периода.
- [ ] Восстановить из бэкапа БП ГИГ если изменений много.
