## Новая настройка

| Ключ | Дефолт | Смысл |
|------|--------|-------|
| `Защита_НеПерезаписыватьПроведённые` | `1` | `1` = повторная загрузка из ЦБ не затирает проведённый бухгалтером документ (расхождение помечается ⚠). `0` = перезаписывать всегда (старое поведение). Можно выключить **без передеплоя** через форму настроек. |

> **Нюанс поведения (подтверждён верификацией, требует ведома бизнеса).** Автосинхронизация
> ЦБ→БП (`tl_sync_cb_bp`) грузит с `Проводить=Ложь` → документы непроведённые → защита
> первой загрузке не мешает; бухгалтер проводит через витрину; повторная автосинхронизация
> уже проведённого — пропускается (это и есть цель). **Но** ручная загрузка через форму
> (кнопки «Загрузить/Обработать пакет») идёт с `Проводить=Истина` → документ авто-проводится
> на первой же загрузке. Тогда повторная загрузка **коррекции** из ЦБ по этому документу
> будет ПРОПУЩЕНА и помечена ⚠ (раньше — молча перезаписывалась). Исправления не теряются
> (видны как ⚠ в витрине), но требуют ручного действия бухгалтера (снять проведение →
> перезагрузить). Топливо/STS-канал НЕ затронут (там другой код, гейта защиты нет). Если для
> сопутки нужна автоперезапись коррекций — ключ `="0"`.

## Как работает защита проведённых (для понимания)

- Документы из ЦБ пишутся **непроведёнными**; проводит бухгалтер через витрину.
- При повторной синхронизации обработчик берёт документ по `ИсточникUUID`:
  - **не проведён** → перезаполняется как обычно (нормальный апдейт);
  - **проведён + из ЦБ пришло аннулирование** → аннулируется (каскад T12);
  - **проведён + данные ЦБ те же** (хеш совпал) → тихо пропускается (доброкачественный
    повторный проход ночной синхронизации);
  - **проведён + данные ЦБ изменились** (хеш другой) → **перезапись пропущена**, ставится
    флаг ⚠, запись в журнал регистрации. Бухгалтер решает: оставить версию БП, либо снять
    проведение вручную и перезагрузить пакет.
