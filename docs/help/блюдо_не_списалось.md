# FAQ: Блюдо продано, а ингредиенты не списались

Бухгалтер видит ОРП с продажей Эспрессо ×3 = 240 ₽, но в ТЧ Товары нет строк ингредиентов (кофе, вода, стакан) — только одна строка «Эспрессо ×3». Списание идёт по «Эспрессо» вместо ингредиентов.

## Что это значит

Расширение не нашло **рецепт** (СпецификациюНоменклатуры) для Эспрессо. Сработал аварийный fallback — блюдо списалось как обычный товар, одной строкой.

## Где увидеть подтверждение

1. Откройте форму **TradeLedger → Загрузка из STS**.
2. Нажмите **«Подробный отчёт ошибок»**.
3. Найдите категорию **НСИ_НеНайдена** (бирюзовый цвет).
4. В таблице должна быть запись с сообщением вида:
   ```
   retail_sale (B): блюдо «Эспрессо 60мл» не раскрыто —
   Для блюда «Эспрессо 60мл» нет спецификации (ТТК не синхронизирован из ЦБ).
   Списано как товар.
   ```

## Возможные причины

### 1. Рецепт ещё не пришёл из центральной базы

Самая частая причина — технолог в ЦБ только что создал блюдо/рецепт, или забыл его сохранить с пометкой «передавать в БП».

**Действие:**
- Сообщите технологу центральной базы что для блюда «N» нет рецепта в БП ГИГ.
- Технолог проверит и пересохранит ТТК.
- В течение нескольких минут пакет с рецептом придёт в БП ГИГ.
- После прихода — откройте «Загрузка из STS» → **«Перезагрузить период»** → **«Да» (Дозагрузить)** для периода когда продавалось блюдо. Расширение пересоздаст ОРП с правильной раскладкой.

### 2. Рецепт есть, но пометен на удаление

Иногда технолог в ЦБ помечает старый рецепт на удаление и создаёт новый. Если новый ещё не успел синхронизироваться — расширение находит только помеченный.

**Действие:**
- Откройте «Все функции → Справочники → Спецификации номенклатуры».
- Найдите блюдо.
- Если есть только помеченные на удаление — ожидайте синхронизацию нового или попросите технолога ускорить.

### 3. Блюдо не отмечено как блюдо в центральной базе

Если в ЦБ для номенклатуры не установлен признак «это блюдо» — пакет придёт с обычным флагом товара, и раскладка не делается даже если рецепт есть.

**Действие:**
- Сообщите технологу: «В пакете блюдо N приходит без признака „ЭтоБлюдо“».
- Технолог поправит в карточке номенклатуры в ЦБ.

### 4. ОРП был создан до 22.05.2026

До этой даты работала старая схема (модель A через 44.01) — блюда не раскладывались. Если бухгалтер смотрит ОРП за апрель — там и не должно быть раскладки.

**Действие:** ничего не делать, это норма для исторических документов.

## Чем грозит «блюдо списано как товар»

### Если на 41.02 есть остаток блюда
- Списание пройдёт нормально с тем остатком который есть.
- Себестоимость спишется по средней (FIFO) цене блюда.
- Прибыль может оказаться искажённой (потому что себестоимость блюда — это синтетическая стоимость, не сумма ингредиентов).

### Если на 41.02 НЕТ остатка блюда
- Получится отрицательный остаток на 41.02 по блюду.
- БП пометит документ предупреждением (если включён контроль).
- Закрытие месяца не сорвётся, но в отчёте «ОСВ по 41.02» будет отрицательное сальдо — нужно объяснять.

## Как избежать

- При запуске общепита на новой АЗС — сначала синхронизировать все ТТК, потом включать продажи блюд.
- В первые дни работы новой АЗС — ежедневно проверять «Подробный отчёт ошибок» на категорию НСИ_НеНайдена.
- Если рецепт меняется в ЦБ — технологу проверять что в БП ГИГ пришла обновлённая версия (через «Все функции → Спецификации номенклатуры → ДатаРедактирования»).

## Что делать с ОРП который уже сформирован неправильно

Если за прошлый месяц ОРП создан с блюдом-товаром, а должно быть с ингредиентами:

1. **До закрытия месяца:**
   - Удалить неправильный ОРП вручную (Помечен на удаление → Удалить помеченные).
   - В форме «Загрузка из STS» — **«Сбросить регистрацию»** для этого периода и АЗС (в подменю «Ещё»).
   - Дождаться синхронизации ТТК.
   - Нажать **«Перезагрузить период»** → **«Да» (Дозагрузить)** — создаст ОРП заново правильно.

2. **После закрытия месяца:**
   - ОРП не переделывается ретроспективно (бухгалтерский принцип).
   - Если расхождение значимое — оформить корректировкой в текущем месяце.
