# Категории записей в подробном отчёте

Расширение записывает в подробный отчёт два типа событий: **ошибки** (требуют действия) и **информацию** (норма, действия не требуют).

Записи видны в окне «Подробный отчёт ошибок» (открывается кнопкой в форме «Загрузка из STS») — там они сгруппированы по категориям и подсвечены цветом.

## Что норма — что требует действия

Из всех категорий ниже:

- **🟢 Информационные** (норма, ничего не делать): Смена_БезПродаж, Смена_БезРозницы, Документ_УжеЗагружен.
- **🔵 Ожидают ручной обработки бухгалтера** (документ создан как черновик): Переклассификация_Топлива.
- **🟡 Внешние причины** (подождать или эскалировать): STS_ОшибкаСервера, STS_ОшибкаСети.
- **🔴 Требуют настройки в БП**: МаппингОплат_НеНайден, ВидОперацииНеСопоставлен, НСИ_НеНайдена, СтавкаНДС_НеСопоставлена, СчётУчёта_НеОпределён, ОбязательноеПолеПусто, ОшибкаПроведения, STS_ОшибкаАвторизации.

## Ошибки на стороне STS (топливо)

### 🟡 STS_ОшибкаСервера

Цвет: жёлтый. Сервер STS (где живёт топливо) не смог отдать данные смены. Чаще всего HTTP 500 — внутренняя ошибка их сервера.

**Это не ваша вина.** Никакие настройки в БП ГИГ это не исправят.

**Что делать:**
1. Подождать 15–30 минут.
2. Нажать «Перезагрузить период» → «Да» (Дозагрузить).
3. Если повторяется больше часа — позвонить в техподдержку pos.autooplata.ru с номером смены.

### 🔴 STS_ОшибкаАвторизации

Цвет: красный. Сервер STS не пустил расширение (логин/пароль не подходит).

**Что делать:**
1. Открыть **TradeLedger → Настройки расширения**.
2. Раздел «Подключение».
3. Проверить Логин и Пароль.
4. Возможно истёк срок токена API — обратиться в обслуживающую организацию.

### 🔵 STS_ОшибкаСети

Цвет: синий. Сервер 1С не может достучаться до STS — проблема со связью.

**Что делать:**
1. Проверить интернет на сервере 1С.
2. Проверить VPN (если используется для подключения).
3. После восстановления связи — «Перезагрузить период» → «Да».

## Ошибки маппинга и сопоставления

### 🟣 МаппингОплат_НеНайден

Цвет: фиолетовый. В смене встретился вид оплаты которого нет в настройках расширения. Например на АЗС подключили новый банк-эквайринг, а в TradeLedger ещё нет записи об этом.

**Что делать:**
1. В подробном отчёте посмотреть в колонке «Значение» — какое имя пришло (например «Газпромнефть»).
2. Открыть **TradeLedger → Маппинг видов оплат STS**.
3. Создать новую запись:
   - Образец имени: часть имени из ошибки (например «газпромнефть»)
   - Канал: выбрать подходящий (cards / online / ledger / voucher / retail_cash / retail_card / writeoff_fuel)
4. После заведения — «Перезагрузить период» → «Да» для смен где была эта ошибка.

### 🟣 ВидОперацииНеСопоставлен

Цвет: фиолетовый. Из центральной базы пришёл документ с видом операции которого расширение не понимает.

**Что делать:** сообщить обслуживающей организации код вида операции (из колонки «Значение»).

## Ошибки справочников БП

### 🩵 НСИ_НеНайдена

Цвет: бирюзовый. Не найден элемент справочника. «НСИ» — это сокращение «нормативно-справочная информация» (контрагенты, номенклатура, склады).

**Норма работы**: НСИ из центральной базы приходит **в каждом пакете** в секции `НСИ` — расширение **автоматически создаёт** недостающие карточки (номенклатуру, контрагентов, договоры, склады) до начала обработки документов. Вручную ничего создавать не нужно.

**Ошибка означает одно из:**
- Пришёл **старый пакет** без секции НСИ (выгружен старой версией ЦБ-расширения).
- В пришедшей секции НСИ конкретный UUID отсутствует (баг ЦБ-выгрузки).
- Автосоздание карточки упало с исключением (см. журнал регистрации БП).

**Что делать:**
1. Открыть форму **TradeLedger → «Перезагрузить период» → «Да» (Дозагрузить)** — расширение попробует прочитать пакет заново. Часто с новой версией пакета карточка создаётся автоматически.
2. Если не помогло — сообщить обслуживающей организации UUID из колонки «Значение» и ИдентификаторПакета — они проверят выгрузку ЦБ.

**Важно — «исторические» записи**: после успешной перезагрузки исходная запись об ошибке в журнале **остаётся**. Это нормально (история событий), но в подробном отчёте они продолжают видны. Проверить «реально открыто или уже исправлено» можно по регистру **TL_СоответствиеИсточников**: если для UUID из ошибки в регистре есть запись — карточка уже создана, ошибка историческая.

В отчёте полного аудита (раздел 7) есть колонка «Исправлено» — туда попадают НСИ-ошибки, для которых маппинг в БП уже создан.

### 🩵 СтавкаНДС_НеСопоставлена

Цвет: бирюзовый. Из источника пришла неизвестная ставка НДС.

**Что делать:** сообщить обслуживающей организации значение (из колонки «Значение»).

### 🩵 СчётУчёта_НеОпределён

Цвет: бирюзовый. В карточке номенклатуры (или в учётной политике) не задан счёт учёта.

**Что делать:**
1. Открыть карточку товара из ошибки.
2. Вкладка «Счета учёта».
3. Задать счёт (обычно 41.02 для розницы).

### 🩵 ОбязательноеПолеПусто

Цвет: бирюзовый. Источник не передал обязательное поле (например цену, или дату).

**Что делать:** проверить документ в центральной базе. Возможно оператор не заполнил какое-то поле. Поправить там, переформировать пакет.

## Ошибки бухгалтерской логики

### 🔴 ОшибкаПроведения

Цвет: красный. Документ создан, но при проведении БП ругается. Например: «Недостаточно остатка для списания», «Не заполнен обязательный реквизит» и т.д.

**Что делать:**
1. В отчёте найти ссылку на документ.
2. Открыть документ в БП.
3. Нажать «Провести» — БП покажет понятное сообщение об ошибке.
4. Устранить причину (восполнить остаток, заполнить реквизит) и провести вручную.

## Информационные записи (норма, действие не требуется)

### 🟢 Смена_БезПродаж

Цвет: зелёный. Смена в STS есть, но в ней нет ни одной продажи (`sales` пуст). Обычно это короткая техсмена кассира на стыке суток (открыл-закрыл за 1-2 минуты, чтобы отделить день N от N+1). Документ ОРП не создаётся намеренно — нечего проводить.

**Что делать:** ничего. Это норма. На некоторых АЗС бывает по 1-2 таких смены в день.

### 🟢 Смена_БезРозницы

Цвет: зелёный. В смене есть только корпоративные операции (топливные карты, онлайн-заправки, ведомости), но нет розничной выручки. Документ ОРП не создаётся, но перемещения на виртуальные склады (Карты/Онлайн/Ведомости) создаются как обычно.

**Что делать:** ничего. Это норма для смен с обслуживанием только корп.клиентов.

### 🟢 Документ_УжеЗагружен

Цвет: зелёный. Пакет/смена уже была загружена в БП ранее. Расширение защищает от дублей и пропускает повторную загрузку. Не ошибка.

**Что делать:** ничего. Если действительно нужна перезагрузка (например, после правки настроек) — использовать кнопку «Перезагрузить период» в режиме «Дозагрузить» — она безопасна.

## Особый случай — нужно ваше участие

### 🔵 Переклассификация_Топлива

Цвет: голубой. В ТТН из STS пришли отрицательные литры — это сезонная переклассификация номенклатуры (например, ДТ зимний → ДТ летний при смене сезона). Парные записи: одна ТТН с минусом по одному виду топлива, в соседней смене — другая ТТН с плюсом по другому виду.

Расширение создаёт **черновики** (непроведённые документы) Списания со знаком «−» — они ждут вашей доработки. Документ Оприходования на «+» делается отдельно через стандартные средства БП.

**Что делать:**
1. Открыть черновик из колонки «Документ».
2. Сверить с парной ТТН (по номеру ТТН).
3. Создать Оприходование топлива на новый вид с теми же литрами.
4. Провести оба документа вручную.

## Прочее

### ❓ Прочее

Цвет: серый. Ошибка не покрытая остальными категориями.

**Что делать:** сделать скриншот, передать обслуживающей организации.

## Как часто проверять

Каждое утро после загрузки смен:
1. В форме «Загрузка из STS» нажать «Подробный отчёт ошибок».
2. Если есть категории — разобрать по этому списку.
3. После устранения — нажать «Перезагрузить период» → «Да» для затронутого периода.
4. Снова открыть отчёт — ошибки должны исчезнуть.
