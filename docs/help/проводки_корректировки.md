# Проводки корректировки поступления (возврат / уточнение)

kind пакета: **`return_purchase`**.

Создаётся документ **КорректировкаПоступления** с видом операции **СогласованноеИзменение** (из Перечисления.ВидыОперацийИсправленияПоступленияРеализации).

## Логика выбора документа

Изначально для возвратов планировался ВозвратТоваровПоставщику, но он требует партионного учёта FIFO для конкретной поставки, что усложняет приём. Поэтому используется КорректировкаПоступления — она работает без явной привязки к партии.

## Проводки

КорректировкаПоступления формирует **обратные проводки** относительно оригинального поступления. На каждую корректируемую позицию:

| Дебет | Кредит | Содержание |
|---|---|---|
| 41.02 | 60.01 | Уменьшение поступления товара (со знаком минус) |
| 19.03 | 60.01 | Уменьшение НДС (со знаком минус) |

Если оригинальный документ оплачен и был автозачёт — корректировка не трогает 60.02, остаётся записью к ручному анализу.

## Структура документа

- Шапка: ссылка на исходное Поступление, организация, договор, склад.
- Табличная часть «Товары»: те же позиции что в оригинале, но с уточнёнными значениями (количество может быть меньше — возврат части; цена — корректировка стоимости).

## Контроль

- Корректировка ссылается на оригинальное поступление. Если оригинал не найден в БП ГИГ — запись попадает в TL_ОшибкиЗагрузки с категорией НСИ_НеНайдена.
- При возврате полной партии — рекомендуется оформлять отдельным документом ВозвратТоваровПоставщику вручную, не через автоматический приём.

## Типовые проблемы

- **Не найдено оригинальное Поступление** — пакет ссылается на ПТУ которого нет в БП. Возможно ПТУ не было загружено или удалено. Проверить TL_СоответствиеИсточников.
- **Партии не совпадают** — характерно при попытке возврата старой партии при FIFO. Поскольку используется КорректировкаПоступления, эта проблема не возникает.
